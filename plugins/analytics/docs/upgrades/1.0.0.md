## What changed

**The first release: analytics as a plugin.** Everything here was the Rocketflare kit's §8 up to
0.5.0. From kit 0.6.0 the kit is bare and this repository is where dashboards live.

What it adds to a kit that installs it:

- **Dashboards** — `analytics_pages` (jsonb `DashboardConfig`, unique slug per tenant, restrictable
  to groups) with `/api/analytics/pages|templates|facts`, the list, view and explore pages, and one
  template, `tenant-overview` ("Organisation Overview"), copied into every organisation by
  `onTenantCreated` and lazily repaired on every `GET /pages`.
- **The semantic layer** — four cubes (`ActivityEvents`, `TenantActivityDaily`, `TenantUsers`,
  `Users`) served by drizzle-cube at `/cubejs-api` and `/mcp`, every one scoping its own `sql()` by
  tenant.
- **One fact table** — `analytics_tenant_activity_daily_facts`, rebuilt per tenant by the
  `15 * * * *` cron, with `rocketflare analytics check-facts` and `refresh-facts` over it.
- **Two CASL subjects** — `Dashboard` (admin+ manage, member read) and `Analytics` (read for every
  role; the cube API is read-only by nature).
- **A contribution seam** — another plugin adds cubes, fact tables, dashboard templates and
  cube-isolation cases through `analyticsExtensions({...})` from `@/plugins/analytics`, declaring
  `requires: { plugins: ['analytics'] }`.

## How to apply

This is the first release; there is nothing to port. Install it:

```bash
pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0   # read the plan
pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0 --apply
pnpm db:generate --name plugin-analytics-1.0.0 && pnpm db:migrate
```

Then the four things a plugin may not do for you, which `pnpm plugin add` prints as numbered steps:

1. **Both wrangler tomls**: `[triggers].crons` gains `"15 * * * *"`, and `[assets].run_worker_first`
   gains `"/cubejs-api"`, `"/cubejs-api/*"`, `"/mcp"`, `"/mcp/*"`. The parity test reads
   `API_PREFIXES`, so a forgotten entry fails your gate rather than silently serving the app shell
   to an `<object>` embed. `pnpm provision cloudflare <env>` writes them.
2. **`apps/web/vite.config.ts`**: add `'/cubejs-api': proxyTo()` and `'/mcp': proxyTo()` to the dev
   proxy; alias `'@nivo/heatmap'` to `./src/plugins/analytics/ui/lib/nivo-heatmap.tsx` (drizzle-cube's
   heat-map chunk names that optional peer and Rollup fails the build without it); add `'recharts'`
   to `resolve.dedupe`.
3. **Dependencies** are declared in the manifest and installed by `plugin add`: `drizzle-cube`
   (pinned exactly), `recharts`, `d3`, `react-grid-layout`, `react-is`, all in `apps/web`.
4. **Check the bundle**: `grep -c recharts apps/web/dist/ui/assets/index-*.js` must stay 0 — every
   page here is `lazy(() => import(...))` and the chart libraries belong in the analytics chunk.

## Conflicts to expect

None on a clean kit at 0.6.0. On an app that has drifted, the rename translator rewrites this
plugin into your vocabulary on the way in, so the conflicts you may see are in the FIVE barrel
lines `plugin add` writes, and only if you have edited them by hand.

**If your app carried the kit's analytics before 0.6.0**, install this plugin BEFORE you run
`pnpm db:generate`. `analytics_pages` and `analytics_page_groups` are unchanged, so their rows
survive untouched. The fact table is renamed to `analytics_tenant_activity_daily_facts` under the
`<id>_*` rule, so `db:generate` emits a `DROP` and a `CREATE` for it (drizzle-kit will ask whether
it is a rename — answer **create table**); it is derived data and the `:15` cron refills it within
the hour, or `rocketflare analytics refresh-facts` does it now.

## Verify

- `pnpm lint && pnpm typecheck && pnpm test && pnpm build` green, including this plugin's own tests
  under `apps/web/src/plugins/analytics/tests/` — in particular `cube-isolation.test.ts`, which
  queries every cube as two tenants and proves each sees only its own rows.
- `pnpm plugin check` exits 0 and lists `analytics`.
- Signed in, **Analytics** appears in the nav and on Home; the seeded **Organisation Overview**
  page renders with live member and activity numbers.
- `rocketflare analytics pages list --json` prints the page; `rocketflare analytics check-facts`
  reports the fact table `fresh` and exits 0.
- An unauthenticated `curl -i <host>/cubejs-api/v1/meta` is a JSON 401, never HTML.
