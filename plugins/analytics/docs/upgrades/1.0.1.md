## What changed

**Installing this plugin no longer leaves the host unable to build.**

drizzle-cube's heat-map chunk imports `ResponsiveHeatMap` from `@nivo/heatmap`, an OPTIONAL peer
that is not installed. Rollup does not treat that as a missing optional — it fails the entire UI
build. The fix has always been to alias `@nivo/heatmap` to the stub this plugin ships at
`apps/web/src/plugins/analytics/ui/lib/nivo-heatmap.tsx`, and that alias lives in
`apps/web/vite.config.ts`, which is a CORE file a plugin may not edit.

So it was printed as a "by hand" step, and `docs/upgrades/1.0.0.md` step 2 still describes it. That
works for a person following an install plan and fails for anything unattended: a CI job that
installs this plugin and runs the gate reads no plans, so it got a tree that could not build — on a
defect belonging to neither the kit nor this plugin, but to the gap between them.

Kit 0.6.1 adds `coreEdits[]` to the plugin manifest: a plugin DECLARES the lines a core file needs
and the HOST writes them, exactly as `bindings[]` declares a resource that `provision cloudflare`
writes. The rule is unchanged — this plugin still edits nothing.

This release declares two of them, both in `apps/web/vite.config.ts`:

- the dev-proxy prefixes `'/cubejs-api'` and `'/mcp'`, after the `'/ws'` line;
- the `'@nivo/heatmap'` alias pointing at this plugin's stub, after the `'@'` alias.

`pnpm plugin add` applies them on install and `pnpm plugin remove` reverts them exactly, so a host
that installs this plugin builds with no hand edits at all.

**Not declared: the `recharts` entry in `resolve.dedupe`.** `coreEdits` inserts lines after an
anchor; it does not modify an existing one, and a measured build without the dedupe entry is clean —
`recharts` stays out of the main chunk and only one file references `react-dom`. It remains worth
adding by hand if you see React duplicated across chunks.

## How to apply

Mechanical, and only if you are on kit 0.6.1 or later — an older kit ignores `coreEdits`, so the
alias stays a hand edit there and nothing breaks.

If you already applied the `vite.config.ts` lines by hand (as `docs/upgrades/1.0.0.md` step 2 told
you to), there is nothing to do: `applyCoreEdits` is idempotent and leaves a line that is already
present alone.

## Conflicts to expect

None. The only changed files are the two manifests, and the change is additive.

## Verify

- `pnpm plugin add <this repo>@1.0.1 --apply` on a clean kit 0.6.1 prints
  `✔ core edit(s) applied to apps/web/vite.config.ts`, and `pnpm build` is green with no hand edits.
- `pnpm plugin remove analytics --apply` returns `apps/web/vite.config.ts` to its original bytes.
- `grep -c recharts apps/web/dist/ui/assets/index-*.js` is still 0.
