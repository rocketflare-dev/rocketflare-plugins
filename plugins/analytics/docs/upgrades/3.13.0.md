## What changed

Analytics offers drizzle-cube's own MCP tools through the app's MCP server as `analytics_discover`, `analytics_validate` and `analytics_load`, and drops its own `/mcp`, which kit 0.41.0 owns.

- The three tools are drizzle-cube's `getCubeTools` (`drizzle-cube/mcp`) adapted to the kit's `Tool` in `tools/cube-tools.ts`: the library's input schemas (through `z.fromJSONSchema`), its descriptions renamed to the `analytics_` names, its JSON answers. They are offered through `ServerPlugin.tools` with `surfaces: ['mcp', 'agents']` — MCP clients and agent runs, never the chat panel — and are read-only (`mcp:read`, listed under the default "all read-only tools" exposure).
- Each call compiles against the same semantic layer as `/cubejs-api` (new `services/semantic-layer.ts`, which the route now uses too), under the security context `/cubejs-api` builds for the same reader, inside the same 20-second statement timeout. `ActivityEvents` stays admin-only. A run with no person behind it, or a reader without `read Analytics`, is offered no tools.
- drizzle-cube's `chart` tool is not offered: it is an MCP App (a UI resource), which the app's MCP server does not serve.
- The tools are pinned: `tests/config/cube-tools-pinned.test.ts` fails when the installed drizzle-cube offers a new, removed or changed tool, so a drizzle-cube upgrade is reviewed tool by tool (the plugin `CLAUDE.md`, "Upgrading drizzle-cube").
- The plugin's `/mcp` is gone: the mount, `/mcp` in `apiPrefixes`, the vite `/mcp` proxy line and the `/mcp` `run_worker_first` step. `createCubeApp` runs with `mcp: { enabled: false }`. `/cubejs-api` is unchanged.
- MCP clients now connect with OAuth through the app's own sign-in at `<APP_URL>/mcp/t/<slug>`. API keys do not work on `/mcp`; an API-key connection to the old analytics `/mcp` (Claude Code `--header`, Claude Desktop through `mcp-remote`) stops working.
- `minKit` is 0.41.0. The `analytics-queries`, `analytics` and `analytics-cubes` skills and the README describe connecting through the app's MCP server.

## How to apply

1. Upgrade the kit to 0.41.0 first (`pnpm kit:upgrade`), then run `pnpm plugin upgrade analytics` in the same sitting, before you start the app or run the gate — kit 0.41.0 refuses to start while a plugin claims `/mcp`, and this release needs that kit.
2. Leave `/mcp` and `/mcp/*` in `[assets] run_worker_first` in both wrangler tomls and the `/mcp` line in `apps/web/vite.config.ts`'s dev proxy — they are the kit's own entries now. If the file has two `'/mcp': proxyTo(…)` lines, delete the analytics one (the line right after `'/cubejs-api': proxyTo(),`).
3. If you passed `mcp: { … }` options (for example `allowedOrigins`) to `createCubeApp` in your copy of `api/routes/cube-api.ts`, delete them: the route now passes `semanticLayer` and `mcp: { enabled: false }`.
4. If a cube of yours reads something from the security context beyond `tenantId`, `userId`, `role`, `groupIds`, `groups`, `groupIdsByType` and `isAdmin`, add it to `toolSecurityContext` in `tools/cube-tools.ts` too, or the MCP tools answer differently from `/cubejs-api`.
5. Tell anyone who connected a client to the old analytics `/mcp` with an API key to remove that connection, then connect again through Settings → MCP's URL (`/mcp/t/<slug>`) with OAuth. Revoke the API keys created for it (Settings → API keys).
6. To offer the tools, an owner or admin turns MCP on at Settings → MCP (the deployment ships it when `FEATURES_ENABLED` names `mcp`, kit `SETUP.md` §2.10).

## Conflicts to expect

- `apps/web/src/plugins/analytics/api/routes/cube-api.ts` → `createCubeApp` takes `semanticLayer` from `services/semantic-layer.ts` and `mcp: { enabled: false }` → keep any other local change around it.
- `apps/web/src/plugins/analytics/index.ts` → the `/mcp` mount and prefix go, `tools` arrives → keep your own mounts.
- `apps/web/src/plugins/analytics/tests/api/cube-isolation.test.ts`, `cube-limits.test.ts` → their `/mcp` cases are replaced by `analytics_load` through `callMcpTool` → take this release's.

## Verify

1. `pnpm gate` is green with the plugin installed, including `tests/api/cube-tools.test.ts` and `tests/config/cube-tools-pinned.test.ts`.
2. `pnpm plugin check` passes and lists `analytics`.
3. With `mcp` in `FEATURES_ENABLED` and MCP on for the organisation, Settings → MCP → Tools lists `analytics_discover`, `analytics_validate` and `analytics_load` under the plugin, each read-only.
4. A connected client's `analytics_load` of `{"measures":["TenantUsers.count"]}` answers the same count as `POST /cubejs-api/v1/load` for the same person.
